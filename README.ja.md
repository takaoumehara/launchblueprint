# launch-blueprint（日本語まとめ）

## 何をするスキルか
新しい商品や大きな機能を作るとき、**コードを書く前に**、AIが会社として必要な全部の面を一枚の「ブループリント」にまとめます。頼まれていないことも含めて見ます。

**v0.2 からは、作業中もずっと先回りします。** 実際のプロジェクトでは、高くついた驚きの多くはキックオフではなく作業の途中で起きました。そこで、決定のたび・オーナーに何かを頼む前・節目の報告のたびに動く手順を追加しました（`references/foresight.md`）。

## 埋める9つの欄
1. 商品とお客さん（誰の、どんな困りごとを、いくらで。最初の1業種・1地域・1プラン。言わないこと、約束しないこと）
2. 値段と原価（1件あたりの原価、月の固定費、無料で出すものの上限、損益分岐点）
3. 技術の構成（置き場所は原則1つ。サービスごとに「無料プランで商用利用できるか・1日のビルド/デプロイ上限とエージェントのpush回数・上限・超えたらどうなるか・入力が学習に使われるか・トークンをどこまで絞れるか・月額・確認日・規約URL」の表。秘密の鍵、費用暴走の防止と停止スイッチ、オーナーが入力する設定名の確認、エージェントに必要なものの一括依頼、複数エージェントのルール、バックアップ、監視）
4. 法律とお金（会社、自宅でない住所、EIN、銀行、保険、売上税/MoR、規約、プライバシー、返金、アクセシビリティ、A2P 10DLC、CAN-SPAM、DMCA、断る業種、弁護士に見てもらう所）
5. 集客とブランド（名前と商標、ドメイン、入口→申込→継続、最初の10件、「AIっぽい見た目」の禁止事項と自動チェック）
6. 運用（手作業の時間、承認が要ること、問い合わせ窓口、レビューが全部終わってからマージ）
7. ライフサイクルとリスク（必須）：休眠アカウント、解約・返金、データの書き出しと削除、亡くなった利用者、違法・著作権コンテンツの削除、チャージバック、障害と補償の上限、責任の上限と訴訟対策、未成年、各国の個人情報法、料金・規約変更の事前通知、サービス終了、乗っ取り対策、情報漏えいの通知、乗り換えの計画、10倍・100倍の費用、ドメインごとのDNSの置き場所、URL登録台帳、共有アカウントの影響範囲、住所が公開される場所、会社設立後に届く営業郵便
8. オーナーのやること一覧（順番、だいたいの日数、何が進むようになるか、外部の待ち時間から逆算した最短公開日）
9. 先回り（v0.2で追加）：提案、プレモーテム、決定の期限、URL登録台帳、ドメイン/DNS表、エージェント環境の一括依頼

## 作業中に動く手順（`references/foresight.md`）
- **A. 決定の先読み**：何かを決めるたびに3行。次に必要になること（2〜3手先）、ほかに変わるもの（URL・秘密鍵・法的文書・費用・別の商品）、誰がいつまでに決めるか
- **B. 頼む前の下見**：オーナーに画面操作やスクショを頼む前に。エージェントがAPIで代わりにできないか、見えるはずの画面を予測、「Xが見えなければYという意味なのでZをする」の分岐、入力する名前を正確に、スクショの前に隠す項目、終わったことを確かめる手順
- **C. プレモーテム**：「半年後に失敗した。なぜ？」を5つ、対策つき。キックオフ時と公開前
- **D. 「頼まれていないが重要なこと」**：節目の報告ごとに上位3つ（お金・法律・取り消せないこと・待ち時間が長いこと・セキュリティ・影響範囲）
- **E. クリティカルパスの暦**：会社設立→税番号→銀行→決済→SMS登録、商標、ドメイン、保険など外部の待ち時間から最短公開日を初日に出し、並行して着手
- **F. エージェント環境の一括依頼と複数エージェントのルール**：必要なもの（通信許可、トークン、環境変数、権限）を最初に1回でまとめて頼む。エージェントごとに1ブランチ、触るファイルの一覧、連絡は1スレッド、マージする人を決める

## 現場の教訓（`references/field-lessons.md`）
実際のプロジェクトで起きた15の落とし穴を「罠・確認方法・いつ確認するか」の表にしています。例：無料プランの1日ビルド上限をエージェントのpushで使い切った、親ブランドのドメインのDNSが別の事業者にありトークンでゾーンを選べなかった、スクショに秘密鍵が写っていた、環境変数の名前を少し間違えて入力した、州の法人登記で自宅住所が公開された、SMSの事業者登録（1〜3週間）に気づくのが遅かった、レビューbotが動いている最中にPRをマージした、など。

## ルール
- 推測しない。分からないことは「NEEDS CONFIRMATION（要確認）」にして、まとめて質問する
- 決めたことには、選ばなかった案と理由を1行ずつ
- 費用は数字で。今・10倍・100倍
- 外部サービスの料金と規約は、毎回その場でページを開いて確認する
- 見直しの時期：公開前、10件目のお客さん、値段を変える前、サービスを足すとき、事故のあと
- 作業中の合図：「決めた」「どれにする」「ドメインを買う」「登録する」「アカウント/トークン/環境変数を設定して」「スクショ」「マージ」「デプロイ」「何か見落としは」

## なぜ作ったか
1つ目の事例：無料プランが商用利用禁止のホストで作ってしまい後で移行が必要になった、費用の上限がそのホストでは効かない作りだった、公開直前に住所や規約の空欄が見つかった。
2つ目の事例（v0.2）：キックオフは問題なかったが、作業中にビルド上限、ドメイン変更に伴う全URLの登録し直し、スクショの秘密鍵、法人登記での住所公開、SMS登録の遅れなどが次々に起きた。どれも1〜2手先を読めば予測できたことでした。（いずれも匿名化）
