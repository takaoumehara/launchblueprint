# 先読みの手順（foresight）：作業の最中に、聞かれていないことを先に出す

提供：CREATIVITY IS EVERYWHERE, LLC ／ 出典：launch-blueprint v0.2 の foresight 手順を一般化（2026-11-03）

キックオフの Blueprint は「1 日目に見えていること」を拾う。高くつく驚きの多くは作業の**最中**に来る：エージェントの push でビルド上限に当たる、移行の途中でドメインが変わる、スクリーンショットに秘密鍵が写る、登記で自宅住所が公開される。この手順はそれを拾う習慣で、1 回ではなく**毎回**回す。
各手順には**引き金**がある。引き金が鳴ったら、オーナーに返事をする前に手順を回し、出力は短く（頼まれていない大事なことを 1 つ出すのが目的で、文章を書くのが目的ではない）。
罠そのものは `catalog/foresight.yaml` の `lessons[]`（`fs.L01`〜`fs.L15`）にある。本文の [L..] はその番号。

| 手順 | 鳴る段（idea / launch / operate / scale / exit） |
|---|---|
| A 決定の先読み | 全段（決定があるたび。多いのは idea・launch） |
| B 画面操作をお願いする前の下ごしらえ | launch（設定・鍵・DNS が集中）、operate（引き継ぎ・更新） |
| C プレモーテム | idea（キックオフ）、launch（公開前）、exit（売却・移管の前） |
| D 「聞かれていないが大事」3 点 | launch・operate・scale（節目の報告のたび） |
| E クリティカルパスの暦 | idea（1 日目）、launch（外部依存が増えるたび） |
| F エージェント環境の一括依頼と複数エージェントの決まり | launch（作り始め）、operate・scale（2 人目が入る時） |

<a id="proc-a"></a>
## A. 決定の先読み

**引き金**：決定が出た、または提案されたとき。オーナーから（「これにしよう」「決めた」）でも、AI から（ホスト・ライブラリ・プラン・ドメイン・名前・ベンダー・データ構造を選ぶ）でも。
「小さい決定」でも省かない。驚きは小さい決定に隠れている。

**手順**：決定の下に 3 行書く。
1. **次に要ること**：2〜3 手先まで、リードタイムつきで。
2. **他に変わること**：URL／秘密鍵／法務文書／費用／他の製品・他のエージェント／戻せるか。
3. **誰がいつまでに決めるか**：オーナーか AI か、期限、何を止めているか。

「他に変わること」で見る場所：
- **URL**：外に登録してある URL 全部（OAuth のリダイレクト、決済の Webhook と戻り先、ボット対策のホスト名、API キーの参照元制限、プラットフォームの API 申請、サイト URL 設定、メール内リンク）。URL 台帳を更新する。[L02][L03]
- **秘密鍵・トークン**：新しいサービス＝新しい認証情報、権限範囲の決定、置き場所。最初の 1 つだけ人が作り、以後は AI が API で作る。[L13]
- **法務文書**：新しいデータの流れ→プライバシーポリシー、新しいベンダー→委託先一覧、新しい連絡チャネル→同意と送信者登録。[L10]
- **費用**：プラン変更、従量課金の追加、上限の要否、無料枠を超えた時の挙動。先に月の上限とキルスイッチを確認。[L14]
- **他の製品・エージェント**：共有のクラウドアカウント、共有ドメイン、共有リポジトリ。影響範囲（blast radius）を書く。[L04][L15]
- **戻せるか**：戻しにくい（ドメイン購入・法人登記・公開リスト掲載・データ移行）なら、そう書いて実行前に聞く。[L08]

決定が URL・秘密鍵・登記・お金に触れるなら、**B**（オーナーの画面操作が要る時）と **E**（リードタイムがある時）も回す。

```
決定：<何を>
→ 次に要ること：<手 1> → <手 2> → <手 3>（リードタイム込み）
→ 他に変わること：<URL / 秘密鍵 / 法務文書 / 費用 / 他製品・他エージェント / 戻せるか>
→ 誰がいつまでに：<オーナー|AI> が <日付> まで。止めているもの：<何>
```

<a id="proc-b"></a>
## B. 画面操作をお願いする前の下ごしらえ

**引き金**：オーナーに画面で何かをしてもらう直前。トークン作成、環境変数の設定、ドメイン購入、DNS 変更、サービス登録、承認、スクリーンショットの送付。

**手順**（結果は依頼メッセージそのものに入れる）：
1. **AI が代わりにできないか**：API・CLI・既存の認証情報で済むなら AI がやって報告する。人に頼むのは、サービスごとの最初の認証情報と、人の身元が要るもの（支払い・本人確認・規約への同意）だけ。なぜ人が要るかを 1 行で。[L13]
2. **画面を予想して書く**：オーナーが実際に見る順に、メニュー名・ボタン名・欄の順番。今の UI を見ていないなら「表示名は違うかもしれない」と断り、クリックではなく各手順の**目的**を書く。[L13]
3. **「〜が見えなければ」の分岐**：黙って失敗しうる手順ごとに 1 行：`<X> が見えなければ <Y> ということ。<Z> をする`。よくある例：ゾーンやプロジェクトが一覧に無い（DNS が別業者にある、トークンのアカウントが違う）、欄の名前が違う、プラン変更が要る、認証待ち。[L02][L13]
4. **識別子を正確に**：環境変数名・権限名・プラン名はコードが期待する通りに。「この名前をそのままコピー」と書く。別名を受け付けるならそう書く。[L06]
5. **スクリーンショットの前に隠す欄**：API キー、秘密鍵、トークン、アカウント ID、メールアドレス、請求情報。「ぼかすか切り取って」と書く。写ってしまったら即座に「この鍵は露出した。回転する。手順はこれ」。[L05]
6. **確認の一手**：最後に 1 つ、オーナーか AI が実行・閲覧して成功を確かめられるもの（設定確認のエンドポイント、CLI コマンド、ログの行、テストリクエスト）。確かめずに「できた」と言わない。[L06]
7. **公開される場所の確認**：登記・登録・掲載・プロフィールなら、入力したデータがどこで公開されるかを入力前に言う。[L08]
8. **費用と戻せるか**：1 行。お金がかかるか、戻せるか、止めるスイッチはどれか。

```
お願いしたいこと：<1 行>　　人がやる理由：<1 行>
手順（見える順に）：
1. …　　<X> が見えなければ <Y>。<Z> をする
2. …
スクリーンショットの前に隠す：<欄>
そのまま入力：<NAME_OF_VAR>（NAME_VAR や NAME_OF_VAR_KEY ではない）
確認：<コマンド / ページ / 期待する結果>
費用・戻せるか：<…>
```

<a id="proc-c"></a>
## C. プレモーテム

**引き金**：キックオフ、公開前、戻しにくい一歩の前（ドメイン変更・法人登記・公開リスト掲載・データ移行・最初の有料広告）。

**手順**：「半年後、これは失敗した。なぜ？」と書き、原因を **5 つ**、それぞれに早期の兆候・対策・担当をつける。`catalog/foresight.yaml` の lessons を種にしつつ、このプロジェクト固有の原因を考える。
- お金／法務・規制／インフラ／人・手順／外部依存 の各分類から最低 1 つ。
- 今は安く防げて、後では高くつく原因を優先。
- 結果はプロジェクト YAML の `risks` に入れ、見直し（SKILL.md §7）のたびに戻る。

| # | 失敗の原因 | 早期の兆候 | 対策 | 担当 | 済 |
|---|---|---|---|---|---|

<a id="proc-d"></a>
## D. 「聞かれていないが大事」3 点

**引き金**：節目の報告、週次の状況報告、PR の要約、進捗について数行を超える返事のすべて。

**手順**：返事の末尾に短いブロックを足す。載せる条件（最低 1 つ満たす）：
- **お金**：変わる費用、無い上限、終わりかけの無料枠。
- **法務**：要る文書・登録・同意・表示。
- **戻せない**：一度やると戻しにくい一歩。
- **長い待ち**：数週間かかるのにまだ始めていないもの。
- **セキュリティ**：露出した秘密鍵、広すぎるトークン、公開された住所。
- **影響範囲**：他の製品・アカウント・エージェントに及ぶ変更。

決まり：3 つだけ（それ以上はプロジェクト YAML の `open_decisions` に置き「他 N 件は Blueprint に」と書く）。各点に具体的な次の行動と日付。オーナーが既に決めたことは繰り返さず `decided` にする。

```
聞かれていないが大事（上位 3 つ）：
1. <点> — なぜ大事か — 提案 — いつまでに
2. …
3. …
```

<a id="proc-e"></a>
## E. クリティカルパスの暦

**引き金**：プロジェクトの 1 日目、および新しい外部依存が現れるたび。

公開日を決めるのはコーディング時間ではなく**外部のリードタイム**。1 日目に最短の公開日を計算し、今すぐ並行で始める項目をオーナーに言う。

典型的な連鎖（国とベンダーごとに確かめる。期間は目安）：
```
法人設立 → 税務番号 → 事業用口座 → 決済事業者の本番有効化
                                  → SMS 送信者登録（国により 1〜3 週間）
ドメイン購入 → DNS 移行 → 証明書 → URL 台帳の更新
商標調査 → 出願（数か月。止めるのは出願でなく調査）
保険の見積 → 加入（数日〜数週間）
プラットフォーム API の申請・審査（アプリストア・地図・メッセージ API：数日〜数週間）
```

| 項目 | 依存 | 着手期限 | 目安の期間 | 最短の完了 | 止めているもの |
|---|---|---|---|---|---|

決まり：
- 最長の連鎖が公開日。「最短の公開日：<日付>。決めているのは <項目>」と書く。
- 1 週間を超えるリードタイムのものは、必要になる時期に関係なく **1 週目に始める**。[L10]
- 何かが遅れたら表を直し、新しい公開日を言う。
- プロジェクト YAML の `open_decisions`／オーナーの to-do に入れる。

<a id="proc-f"></a>
## F. エージェント環境の一括依頼と複数エージェントの決まり

### F1. 環境の前提を 1 回でまとめて頼む [L12]

**引き金**：AI が外部サービスに触れる作業を始める前、およびサービスを足すたび。

前提を 1 つずつ頼まない。全部を 1 通にまとめる。

| 要るもの | なぜ | 権限範囲（最小） | 誰が作る | 置き場 | 確認方法 |
|---|---|---|---|---|---|
| `api.example.com` への通信許可 | デプロイ / API 呼び出し | そのホストだけ | オーナー | エージェント設定 | `curl` で疎通 |
| <サービス> の API トークン | <作業> | <プロジェクト> の読み取りのみ | オーナー（最初の 1 つ） | ホストの秘密情報 | 設定確認 |
| 環境変数 `EXAMPLE_API_KEY` | <作業> | — | オーナー | ホストの環境変数 | 設定確認 |
| 権限：<操作> | <作業> | <プロジェクト> | オーナー | — | 試し実行 |

決まり：
- 動く範囲で最小の権限。アカウント全体しか選べないなら、そう書いて影響範囲（他に何に届くか）を名指しする。[L04]
- 最初の認証情報ができたら、以後のトークン・鍵・設定は AI が API で作る。[L13]
- デプロイ・ビルドの上限：プランの 1 日の上限と、エージェントの push 頻度の見込みを書く。上限に近づくなら、まとめて push・プレビュー専用ブランチ・プラン変更を、本番が止まる前に提案する。[L01]

### F2. 複数エージェントの決まり [L15]

**引き金**：同じリポジトリ・アカウントで 2 つ目のエージェント（または 2 人目の人）が作業を始める前。

最初の並行コミットの前に、書面で合意する：
1. **エージェントごとに 1 ブランチ**：`<agent>/<task>`。互いのブランチに push しない。
2. **作業ボード**にエージェントごとの「触るファイル」。重なるなら先に話す。
3. **調整は 1 つのスレッド**。決定はそこに書き、コミットメッセージに書かない。
4. **マージする人は 1 人**。レビュアー全員（人・レビューボット・CI・デプロイのプレビュー）が終わって報告してからマージ。[L11]
5. **共有リソース**：デプロイ上限・API 割当・環境変数の持ち主を決める。共有設定を変えるのは 1 エージェント、他は読むだけ。
6. **名前の接頭辞**：共有アカウントで作るもの（プロジェクト・トークン・バケット・DNS レコード）には `<product>-` を付け、影響範囲が見えて後片付けできるようにする。[L04]
