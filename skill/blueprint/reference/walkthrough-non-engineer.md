# エンジニアでない人のための Blueprint の歩き方

English summary: a step-by-step walkthrough of the web app for someone who does not write code. Four intake answers → a map of 60 decisions in five stages → decide one at a time (accept the AI pick or choose) → export YAML and hand it to an AI agent. The last section lists the friction found while writing this and what was fixed.

提供：CREATIVITY IS EVERYWHERE, LLC。見本は「小さなスタジオの予約アプリ」。実在のプロダクト名・人名は入れません。

## 0. 用意するもの（5分）

- パソコンのブラウザ。スマホでも動きますが、地図の線はパソコンでだけ出ます。
- アプリを自分で動かす場合：`app/` で `npm ci && npm run dev`。表示された URL を開きます。配布済みの URL があればそれを開くだけです。
- 答えはこのブラウザの中だけに保存されます（サーバーには送りません）。別のブラウザで開くと空になります。

## 1. 「01 始める」— 4つ答える

1. **名前**：仮でかまいません（例：スタジオ予約）。
2. **ひとことで目的**：誰の、どんな困りごとを、どう楽にするか（例：電話と現金のやり取りなしで予約と支払いを受ける）。
3. **誰のため**：自分や知り合い／一般のお客さん／会社やお店。スタジオ予約なら「会社やお店」。
4. **どこで使う**：ウェブサイト／スマホアプリ／両方。まずはウェブ。
5. **お金**：無料／有料／ユーザー同士で売り買い。スタジオが代金を受けるなら「有料」。
6. **どの国の人向け**：アメリカ／日本／複数の国。

「地図を見る →」を押します。答えを変えたくなったら、地図の右上「EDIT ANSWERS」からいつでも戻れます。答えを変えると AI のおすすめが変わります（例：「スマホアプリ」にすると、データの置き場所のおすすめが変わる）。

## 2. 「02 地図」— 読み方

**上の帯（6つの段）**
左から 構想 → 作る → 出す → 回す → 増やす → 終える。大きな数字は「決めた数」、小さい数字は「その段で決めることの数」。数字の下の小さな四角は決めること1件ずつで、枠だけ＝未決、白＝AI のおすすめがある仮の状態、オレンジ＝あなたが決めた。段を押すと、その段の決めることだけが明るくなります（もう一度押すと戻る）。

**6つの列**
BRAND（ブランド・発信）／UX（体験・届け方）／UI（画面）／TECH（しくみ）／BIZ・LEGAL（お金・会社・法律）／RULES（守ること）。

**点**
白枠＝未決、白＝仮（AI のおすすめあり）、オレンジ＝決定。点の下の小さな字は今の状態と、選ばれているもの。列が混んでいる時は字を隠し、点に触れると出ます。

**線**
「先に決めること → あとで決めること」のつながりだけを引いています。飾りの線はありません。両端が決定になると線がオレンジになり、「決めた道すじ」が浮かびます。キーボードの T で、道すじだけの表示に切り替わります。

**まずここから**
左下に、今すぐ決められるもの（先に決めることが全部決まっているもの）を3つ出します。迷ったらここから。

**右下の大きな数字**
決めたステップの数（TRACE）。

**左下のリンク**
CATALOG（カタログ画面へ）、/DATA.JSON と /LLMS.TXT（AI が読む生データ）。

## 3. 「03 決める」— 1件ずつ

決めることは2種類あります。

**選ぶもの（choose）**：選択肢から1つ。上に「AI のおすすめ」とその理由。あなたの4つの答えから決まったおすすめには「あなたの答えから」と付きます。
- 納得したら「おすすめで決める」。
- 別のものが良ければ、その選択肢を押してから「選んだものに決める」。
- 「選ばなかったものと理由」が自動で並ぶので、あとで見返せます。
- しくみ（TECH）の決めることには下に **スタック比較** が付きます。1 似たサービスと無料枠、2 1社でそろえるか組み合わせるか、3 お金を払った方が楽になる境目、4 おすすめと選ばなかった理由。

**確認するもの（checklist）**：全部に目を通してチェックすると「確認したので決定」が押せます。

**タグの意味**
- 「確認済み 2026-10-28」：公式ページで確かめた日。
- 「未確認 — 使う前に公式で確認」：記憶や推測の値。使うと決めた時に公式ページを見てください。
- 「AI用ID」：AI に渡す時の名前（例 `db.supabase`）。横の「カタログ」リンクで、その分野の全項目が見られます。

**つながり**（右側）
先に決めること／これで決まること。先に決めるものが未決でも決められますが、「先に『〇〇』を決めると楽です」と出ます。

決めると地図に戻り、点がオレンジに、段の数字が1つ増えます。「未決に戻す」でいつでも取り消せます。

## 4. 「04 カタログ」— AI が読む全部

34 の分野、407 項目。各分野の行の四角は項目1つずつで、オレンジは地図の決めることにつながっている項目。分野を押すと、項目ごとに「内容・向いている・向かない・なぜ・確認・費用・出典」と、どの決めることで使われるかが見られます。地図に出てこない分野（見本のキャンバス、鮮度の決まり、網羅表）もここにあります。

## 5. 書き出して AI に渡す

地図の右上「EXPORT YAML」（AI 用）か「MARKDOWN」（人が読む用）。YAML は `project-map.template.yaml` と同じ形で、決めたこと・AI のおすすめ・選ばなかった理由・段・先に決めることが全部入っています。

AI エージェントに渡す時の言い方（例）：

```
この project-map.yaml が今の決定です。status: decided のものは変えないでください。
status: open のものは、Blueprint の MCP（get_comparison / get_item）で選択肢を調べて、
おすすめと理由を1つずつ私に聞いてから進めてください。未確認（verified: false）の
料金は「未確認」と言ってください。
```

## 6. 見本を通して見つかった引っかかり

直したもの（この版で）：

| 引っかかり | 直したこと |
|---|---|
| 最初は白い画面で、説明や試作の黒い画面と違って戸惑う | 黒を既定にした。右上で切り替え可 |
| どこまで進んだか分からない | 上の帯に段ごとの数字と四角を出した |
| 「仮」と「決定」の違いが分からない | 読み方の凡例に書き、帯の四角も白／オレンジで分けた |
| 構想の段に「困りごとを確かめる」が無く、いきなりブランドから始まる | 「困りごとの確かめ」を足した |
| 有料なのに規約・返金・税を決める場所が無い | 「規約・返金・税の決まり」を出す段に足した |
| 「1日目から残す数字」「きれいに終わる」が無く、回す・終える段が薄い | 両方を足した |
| AI が読む分野の多くが画面に出てこない | 「04 カタログ」を足し、項目から決めることへ行き来できるようにした |
| しくみの列が混んで、点の下の字が重なる | 混んでいる時は字を隠し、触れた時だけ出す |
| スマホで段の帯が2回出る | 1回にした |
| 最初からやり直す方法が無い | 「01 始める」に「最初からやり直す」を足した（確認してから全部消す） |

まだ直していないもの（次の版の候補）：

1. 書き出した YAML を**読み戻す**ことができない（アプリ → AI の一方通行）。
2. 画面の言葉は日本語だけ。英語の人は QUICKSTART.md を読む。
3. 予約アプリに特有の決めること（予約枠の管理、SMS の催促、無断キャンセルの決まり）はカタログに無い。
4. 「仮」のまま全部を一括で決定にする手段が無い（1件ずつ押す。見本で41回）。
