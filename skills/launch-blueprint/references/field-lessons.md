# Field lessons (checklist)

Fifteen traps from one real project: a done-for-you local-presence service for small trades, built by AI agents for a non-technical owner. All details are anonymized. Each row says how to check for the trap and which trigger should make you check. Procedures referenced as A–F are in `foresight.md`.

Use this as a checklist at kickoff and again whenever the trigger in the last column fires.

| # | Trap | How to check | When (trigger) |
|---|---|---|---|
| L1 | Host's free plan forbade commercial use **and** had a daily deployment/build cap (about 100/day). Frequent agent pushes exhausted it, blocking previews and production. | Open the plan page: commercial use allowed? Daily/monthly build and deploy caps? Estimate agent push rate (pushes per agent per day × agents). If rate approaches the cap, batch pushes, use a preview-only branch, or change plan before it blocks. Record in `vendor-check.md` table. | Choosing a host; adding an agent; first week of work (F1) |
| L2 | The parent brand domain's DNS was not on the planned cloud provider, so a scoped API token could not select the zone. The owner bought a product domain mid-migration. | At kickoff, list every domain and subdomain in play with registrar and DNS host for each (template §9 domain/DNS table). Decide the product's canonical domain **before** wiring anything URL-dependent. Verify the token can see the zone before writing DNS steps. | Kickoff; before any OAuth, webhook, bot-protection, or API-app setup (A, B) |
| L3 | Changing the domain meant editing every place a URL was registered (OAuth redirect URIs, payment webhooks and return URLs, bot-protection hostnames, API-key referrer restrictions, platform API applications, site URL config). | Keep a URL registry from day one (template §9): every external place a URL is entered, with the value and who can change it. Update it on every decision that touches a URL (A). | Any URL-dependent setup; domain change; environment change |
| L4 | The cloud account also hosted a sibling product; any account-scoped token could reach it. | State the blast radius of every token and account: what else it can read, write, or delete. Propose a separate account, or strict naming prefixes plus agent rules (F2 rule 6). Prefer project-scoped tokens; if none exist, say so. | Creating any token; adding an agent; F1 batch request |
| L5 | A screenshot the owner sent showed a secret key in plain text. | Before asking for any screenshot of a settings page, list the fields to hide. If a secret appears anyway, say so at once and give rotation steps. Never paste the value back. | Before asking for a screenshot (B step 5); on receiving any image or paste |
| L6 | The owner entered an env var under a slightly different name (`FOO_API` instead of `FOO_API_KEY`). | Give the exact name and say "copy exactly". Accept aliases in code or provide a settings-check endpoint/command. Always give a post-entry verification step. | Asking the owner to enter any config (B steps 4 and 6) |
| L7 | Generic "AI-looking" UI shipped and was rejected: one-side colored accent stripes on cards, emoji-as-icons cards, blue-purple gradients. | Set visual prohibitions in writing before the first screen (sections.md §5) and add an automated guard test (lint or snapshot grep for the forbidden patterns) that fails CI. | Before first UI work; adding a design system |
| L8 | The state business filing published the owner's home address. | Before any filing, registration, or listing, list where an address becomes public: state entity records, WHOIS, maps/business profiles, payment statement descriptors and receipts, email footers required by anti-spam law, app stores, terms pages. Arrange a registered agent and a business mail address first. | Before any filing, registration, domain purchase, listing, or profile (B step 7; `lifecycle-risk.md` §17) |
| L9 | After forming the entity, expensive solicitation mail arrived: look-alike "compliance" and "certificate" offers. | Warn the owner in advance: which mail is official (from the state agency, the tax authority, the registered agent) and which is an upsell. Tell them to ask before paying anything that arrives by mail. | Right after entity formation; in the D digest for that milestone |
| L10 | SMS carrier registration (A2P 10DLC) takes 1–3 weeks and was raised late. | Build the critical-path calendar (E) on day one: tax ID → bank → payment processor live → SMS registration; plus trademark, domain, insurance, platform API applications. State the earliest launch date and start all long-lead items in parallel immediately. | Day one; adding any external dependency (E) |
| L11 | A PR was merged while an automated code review was still running. | Before merging, confirm every reviewer has finished: humans, review bots, CI, deploy previews. "Checks pending" means wait. | Before every merge (F2 rule 4; sections.md §6) |
| L12 | Agent-environment needs (network allowlist for an API host, API token, permissions) were requested one at a time. | Batch every prerequisite into one early request (F1 table): need, why, narrowest scope, who creates, where it lives, how to verify. | Before the agent's first external call; when adding a service |
| L13 | On-screen instructions for creating a token did not match what the owner saw (zone not listed; secret-entry form different from expected). | Predict the screen before sending steps. Add "if you don't see X, it means Y — do Z" branches. Prefer the agent doing it via API once one credential exists; explain why the first credential must be human-made. | Before sending any UI steps (B steps 1–3) |
| L14 | The owner wanted free AI models (free tiers, free routers). | Check for each: are inputs used for training? Is commercial use allowed? Regional restrictions? Rate limits and availability? Keep a paid fallback under a global monthly spend cap with a kill switch, and check the cap **before** consuming a free quota. Cache keys must include every input dimension (model, prompt version, locale, customer) so cached results are not served across inputs. | Choosing any AI provider or free tier; `vendor-check.md` |
| L15 | Two AI agents worked in parallel on one repo without rules. | Before starting: one branch per agent, a work board with "files I touch", a single message thread, and a named merger (F2). | Before a second agent or person starts on the repo |

## Cross-cutting rules that came out of the same project

- **Global monthly spend cap with a kill switch, checked before consuming a free quota.** A free tier is not free if the fallback is uncapped. (L14; sections.md §2, §3)
- **Cache keys include every input dimension.** Otherwise one customer's cached answer is served to another. (L14; sections.md §3)
- **The first API credential is human-made; after that the agent automates via API.** Say this at the first credential request so the owner knows why it will not happen again. (L13; foresight B step 1)
- **Decide the canonical domain before wiring anything with a URL.** (L2, L3; foresight A)
- **State the blast radius whenever a token or account is shared.** (L4; foresight F1)
